### CliDeck
- URL: https://clideck.dev/
- Kind: agent-native
- What: CliDeck is a local browser-based terminal dashboard and multi-agent workspace for running, monitoring, and coordinating CLI coding agents (Claude Code, OpenAI Codex, Gemini CLI, OpenCode, Pi, and arbitrary shell sessions) side-by-side in one window; does it have a KANBAN/board view of agent tasks: no (it uses a WhatsApp/chat-style session sidebar grouped by project with live working/idle status dots, rather than a column-based kanban board).
- Agent integration: CLI wrapper around real terminal sessions (PTYs), local OpenTelemetry (OTLP) receiver on port 4000 (`POST /v1/logs`) for Claude Code, Codex, and Gemini CLI status/telemetry; plugin bridge for OpenCode; CLI commands `clideck ask <agent> "<prompt>"` for agent-to-agent delegation, `clideck agents` for discovery, and `clideck show <file>` for previewing artifacts; supported agents include Claude Code, OpenAI Codex, Gemini CLI, OpenCode, Pi, and custom CLI agents.
- Mobile: PWA / responsive web via end-to-end encrypted mobile relay (`clideck-remote` pairing QR code using ECDH P-256 + AES-256-GCM via Cloudflare Worker relay; note that v2 README notes standalone mobile remote was streamlined in v2 while docs at docs.clideck.dev/mobile document the web-based pairing interface; no native iOS or Android app).
- Pricing: free / open-source free (MIT licensed; 100% free with no paid tiers; mobile remote free tier previously limited to one active paired session at a time).
- Self-host: yes (local CLI/server installed via `npm install -g clideck` or `npx clideck`; runs on localhost:4000; all data stored locally in `~/.clideck-next` or `~/.clideck`; no cloud account, no telemetry sent to third parties).
- License: MIT
- Activity: Active / v2.4.0 (GitHub repository rustykuntz/clideck; package.json version 2.4.0; actively maintained as of late 2026).
- Pros: True local execution with zero vendor lock-in or telemetry leaks; Native OTLP integration with Claude Code and Codex for zero-overhead idle/busy detection without scraping prompt content; CliDeck Ask enables cross-agent peer delegation and artifact previewing (`clideck show`) alongside terminals; Project-based grouping and instant session resume using agent native flags.
- Cons: No native kanban board or visual task dependency graph (chat/terminal list only); Autopilot workflow router was removed in v2 in favor of agents' own subagent systems; Mobile experience is browser/relay-only with no push notifications or native mobile apps; Setup requires locally installed Node.js 22.12+ and CLI agent binaries.
- Sources: https://clideck.dev/, https://yetanotherorchestrator.app/apps/clideck/, https://docs.clideck.dev, https://docs.clideck.dev/mobile, https://docs.clideck.dev/agents/overview.md, https://docs.clideck.dev/features/telemetry.md, https://docs.clideck.dev/features/sessions.md, https://docs.clideck.dev/features/autopilot.md, https://github.com/rustykuntz/clideck
- Confidence: high

### Fusion
- URL: https://runfusion.ai/
- Kind: agent-native
- What: Fusion is an open-source software factory and multi-node agent orchestrator that automates specification, planning, execution, review, and auto-merging across isolated git worktrees; does it have a KANBAN/board view of agent tasks: yes (features a rich visual Kanban board with Planning/Triage, Todo, In Progress, In Review, and Done columns, interactive node dependency graph views, and per-step verification gates).
- Agent integration: Direct CLI (`fn` / `fusion` CLI built with Bun/Node), REST/SSE APIs (`/api/automations`, `/api/routines`, `/api/auth`), inter-agent mailbox messaging (`fn_history_read`, agent mail), Agent Client Protocol (ACP) and Model Context Protocol (MCP) interop (driving Claude Code, Gemini CLI, Cursor CLI, Droid/Factory AI, Hermes, Paperclip, OpenClaw, Ollama, OpenAI Codex, and custom providers).
- Mobile: Native iOS app & native Android app (built with Capacitor and distributed for App Store & Google Play) plus installable PWA and responsive web dashboard (detailed in MOBILE.md and runfusion.ai mobile showcase).
- Pricing: free / open-source free (MIT licensed; zero-cost self-hosted open source; users bring their own LLM API keys or local models via Ollama/llama.cpp; no commercial SaaS subscription paywall as of October 2026).
- Self-host: yes (self-hosted via Docker container, npm `@runfusion/fusion`, Homebrew `brew install runfusion/fusion/fusion`, or single standalone Bun binary; uses embedded zero-config PostgreSQL for local metadata with support for external shared PostgreSQL in multi-node meshes; mesh networking across local LAN, Tailscale, or Cloudflare tunnels).
- License: MIT
- Activity: Highly active / 0.78.0-beta.7 (GitHub repository Runfusion/Fusion; active releases shipping weekly, latest v0.78.0-beta.7 in October 2026; over 1,300 issues/PRs tracked).
- Pros: Full-featured visual Kanban board, dependency graph, and Command Center with real-time token/cost/vital observability; Strict multi-phase quality gates (Plan -> Review -> Execute -> Review) and automated git worktree isolation preventing merge collisions; Complete cross-platform ecosystem with native mobile (iOS/Android), desktop (Electron), and web; Rich inter-agent collaboration with multi-agent chat rooms, agent mailbox, and support for 440+ agent companies via companies.sh / Paperclip.
- Cons: Heavy footprint compared to simple terminal wrappers (bundles embedded PostgreSQL, multi-package pnpm workspace, and complex runtime services); Steeper learning curve with dozens of configurable model lanes, oversight policies, and workflow graphs; Reviewer gates can be pedantic and require machine-readable verdicts before tasks can auto-merge; Local compilation and setup can be resource-intensive on constrained machines.
- Sources: https://runfusion.ai/, https://yetanotherorchestrator.app/apps/fusion/, https://github.com/Runfusion/Fusion, https://github.com/Runfusion/Fusion/blob/main/CHANGELOG.md, https://github.com/Runfusion/Fusion/blob/main/package.json, https://github.com/Runfusion/Fusion/blob/main/packages/core/package.json
- Confidence: high

### jat
- URL: https://jat.tools/
- Kind: agent-native
- What: jat (Just Another Terminal / jatstack) is a self-hosted, local-first agentic IDE and multi-agent orchestrator built with SvelteKit and tmux that supervises fleets of 20+ parallel coding agents with shared task tracking, git worktree isolation, and a serial merge queue; does it have a KANBAN/board view of agent tasks: no (its primary task interface is a CLI task queue `jt` / `jat-task` combined with SvelteKit web dashboards for Epic Cockpit `/epics`, `/tasks` lists, Monaco editor `/files`, and tmux terminal split views, rather than a drag-and-drop kanban board).
- Agent integration: CLI task engine `jt` (`jat-task` / `jat-tasks`) with machine-readable JSON flags (`jt ready --json`, `jt update <id> --status in_progress`, `jt close`), agent mailbox CLI (`jat-send`, `jat-inbox`), agent slash commands (`/jat:start`, `/jat:complete`), external trigger integrations (spawning tasks from Slack, Telegram, RSS, Gmail), and support for Claude Code, OpenAI Codex, Gemini CLI, Aider, and any tmux CLI agent.
- Mobile: responsive web / none official (SvelteKit web interface accessible via mobile browser over Tailscale / SSH tunnels; no native iOS or Android apps, no dedicated PWA manifest advertised).
- Pricing: free / open-source free (MIT licensed; completely free and self-hosted with no subscriptions or paid tiers; users provide their own agent subscriptions or API credentials).
- Self-host: yes (100% self-hosted local-first architecture; installed via shell bootstrap `curl -fsSL jat.tools/install | sh`; runs on `localhost:3333` with local SQLite storage and tmux sessions; optionally deploys to remote Linux VPS or appliance compute nodes via Tailscale mesh `jat.run` / `jat-appliance`).
- License: MIT
- Activity: Active indie project / master branch rolling releases (GitHub repository jatstack/jat formerly joewinke/jat; created late 2025, daily commits through mid/late 2026; ~242 stars in summer 2026; continuous master commits without formal semantic tag releases).
- Pros: Complete local-first agentic IDE combining Monaco code editor, git diff viewer, task manager, and agent terminals in one lightweight SvelteKit app; Composable 7-tool jatstack ecosystem (jat-pilot for browser automation, jat-secret for zero-knowledge vault, jat-appliance for compute offload, jat.run for inference mesh, jatstation for desktop dotfiles); Autonomous trigger system capable of spawning agent runs from Slack, Telegram, RSS, or cron schedules; Worktree isolation with a serial merge queue preventing code clobbering.
- Cons: No kanban card board view (relies on list queues and terminal dashboards); Setup depends on tmux and unix command-line tools (macOS and Linux only, no native Windows support); Bus factor of one (developed and maintained primarily by solo creator Joe Winke); Tiny community and lacks formal semantic release tags (ships directly to master).
- Sources: https://jat.tools/, https://jat.tools/docs/jat, https://jat.tools/reference, https://jat.tools/docs/jst, https://jat.tools/docs/jat-pilot, https://jat.tools/docs/jat-appliance, https://jat.tools/docs/jat-secret, https://jat.tools/docs/jat-run, https://jat.tools/docs/jatstation, https://yetanotherorchestrator.app/apps/jat/, https://rywalker.com/research/jat, https://github.com/jatstack/jat
- Confidence: high
