## Verification method

- Isolated harness, no production data touched: a Bun mock of `/api/tracker/*` on `127.0.0.1:9121` (reads seeded from the live gateway's `/api/tracker/bootstrap`; every write kept in memory) plus the repo's own Vite dev server on `127.0.0.1:5199` serving `web/src`.
- Gated, not timed: requests on the paths under test stay pending until the harness releases them (`/__ctl/gate`, `/__ctl/pending`, `/__ctl/release`), so no assertion depends on a fixed sleep or on timing luck. Every WebView call is deadline-wrapped (8-25 s) and the whole run is capped at 150 s.
- Fixed-source run: 11/11 checks pass - D23 (3 desktop), D25 (2), D28 (2), D29 (2), plus 2 mobile checks. Machine-readable: `ui/results-fixed.json`.
- Counterfactual run (`ui/counterfactual.sh`): each fix was temporarily reverted, the suite re-run, and the file restored with an md5 match; in every case exactly that item's checks failed and the other items' checks stayed green. Restored hashes match the ones quoted at the top of this file.
- Desktop 1440x900 and mobile 390x844 (Bun.WebView, macOS WebKit). Mobile checks: search results render with `scrollWidth == clientWidth == 390`; the milestone add form is reachable at 390 px with no horizontal overflow (`ui/mobile-search.png`, `ui/mobile-milestone.png`).
- Owned processes (mock server, Vite, WebView) were closed and ports 9121 / 5199 verified free after the run.

## Unverified / gaps

- The UI was exercised against Vite-served sources, not the shipped `web/dist` bundle; nothing was built, per the owner rule. A stale-bundle regression would not show up here.
- The mock is a hand-written stand-in, not the Rust server: no real latency, no real `lane_not_verified` 409, and no cycle-overlap validation (the server has none). D26 and D27 were therefore not exercised end-to-end in a browser - both depend on the real backend (a subscriber round-trip; a 409 from a lane-backed close) and are recorded above as the other lanes' claims plus the current code at the cited lines.
- Only macOS WebKit via Bun.WebView. Safari/Firefox/Chrome-specific behavior and real touch input are untested; mobile was verified by viewport, not by device.
- D23's cancellation is a flag, not an AbortController, so the request still runs to completion server-side after the query is cleared; that is unchanged by this item and not asserted here.
- No automated test was added for any of the four items: web/src has no `.test.tsx` at all and `vitest.config.ts` sets `environment: "node"`, so there is no existing component seam to extend. The counterfactual harness is the regression evidence and it lives under `.omo/evidence/review-20261020/ui/`, not in the test suite.
