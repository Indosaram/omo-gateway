## VERDICT

PARTIAL

- **Runtime failed-send claim query (`DeliveryLedgerService::sweep_failed_for_runtime`)**: IMPLEMENTED
  - Scans `failed` obligations owned by the current process instance (`owner_pid` and `owner_started_at`).
  - Scopes to specific `bot_id` via `SessionKey`.
  - Filters for retryable transport errors and excludes timeouts and 403 Forbidden errors.
  - Enforces attempt limits and staleness limits.
  - Atomically transitions state from `failed` to `attempting` and increments attempts.
- **Direct replay without agent execution (`DiscordEgress::replay_failed_transport_obligations`)**: IMPLEMENTED (standalone method)
  - Replays obligations directly via `OutboundAction::SendMessage` and updates delivery state in the ledger.
  - Never resubmits to LLM backend, spawns another daemon, or resets conversation session (satisfies NO agent replay rule).
- **Transport reconnect / resume lifecycle wiring**: ABSENT
  - `replay_failed_transport_obligations` is NEVER invoked by any production runtime code (`src/main.rs`, `src/discord/adapter.rs`).
  - In `src/discord/adapter.rs`, `FullEvent::Ready` only triggers missed message backfill; `FullEvent::Resume` is unhandled.
  - Only caller in the repository is the isolated unit test `tests/test_discord_adapter.rs:4300`.
- **Catch-up for late-persisted failures after reconnect**: ABSENT
  - No check exists when recording obligation failure to trigger redelivery if the transport is already restored (`gateway/platforms/base.py:3644-3665` race condition).
- **Unsent claim release without consuming attempts**: ABSENT
  - No ledger API exists to release a claimed obligation back to `pending`/`failed` without consuming an attempt budget (`gateway/delivery_ledger.py:189-207`).
- **Typed transport error disposition**: ABSENT
  - Retryability relies on substring matching on `last_error` rather than typed disposition at Discord egress.

## RESIDUAL

1. **Reconnection/Resume lifecycle event wiring**:
   `DiscordEgress::replay_failed_transport_obligations` is never called by runtime event handlers. Wiring is needed in `handle_event` for `FullEvent::Ready` and `FullEvent::Resume` (or on shard reconnection hooks) with access to the egress dispatcher or `DiscordEgress` instance for the reconnected `bot_id`.
2. **Catch-up for late failure recording after reconnect**:
   When an outbound send fails and is persisted to `delivery_obligations` via `mark_obligation_failed`, if the transport has already reconnected in the interim (closing the race described in `gateway/platforms/base.py:3644-3665`), there is no check or trigger to immediately schedule redelivery of the newly failed obligation.
3. **Claim release API without consuming attempts**:
   `DeliveryLedgerService` lacks a `release_claim` method to safely return an obligation from `attempting` back to `failed` or `pending` without incrementing or burning an attempt count when sending cannot start (`gateway/delivery_ledger.py:189-207`).
4. **Typed egress error disposition**:
   Currently, retryable classification relies on substring matching against `last_error` in `sweep_failed_for_runtime`. Discord egress error handling does not produce a typed `DeliveryDisposition` (distinguishing connection-shaped drops from timeout ambiguity and HTTP rejections).

## CLAIM

REMAINING: U73 live reconnect/resume lifecycle wiring, late failure catch-up, unsent claim release, and typed egress error classification remain unimplemented in production runtime.
