## VERDICT

PARTIAL

- **Production callers of `record_obligation`**: IMPLEMENTED
  - Both `src/cron/scheduler.rs` and `src/agent/omo_backend.rs` record outbound delivery obligations before platform dispatch in production paths.
- **Failed final Discord dispatch contract in `omo_backend.rs`**: IMPLEMENTED
  - Final emission records an obligation, attempts dispatch, marks the obligation failed on dispatch error, propagates `Err` via `delivered?;`, and inhibits execution of `cron_ack_command`.
- **Startup recovery sweep replay guard in `src/main.rs` / `src/ledger/service.rs`**: IMPLEMENTED
  - Replay selection is guarded by both `owner_pid` and `owner_started_at` (RFC3339 process start stamp via `migrations/0020_obligation_owner.sql`). Reused PIDs from previous incarnations are not stranded.
- **Obligation statuses in `src/ledger/service.rs`**: IMPLEMENTED
  - `DeliveryObligationState` supports `pending`, `attempting`, `delivered`, `failed`, and `abandoned`. Stale and retry-exhausted rows transition to `abandoned`.
- **Durable obligation retention/pruning (`prune_terminal_obligations`)**: PARTIAL (DEAD CODE)
  - Method `DeliveryLedgerService::prune_terminal_obligations` is implemented (`src/ledger/service.rs:541-584`) with time cutoff and row count bounds matching Hermes `gateway/delivery_ledger.py:276-304`.
  - However, it has ZERO callers across `src/` (not called during startup sweep in `src/main.rs`, nor opportunistically on `record_obligation` like Hermes `delivery_ledger.py:178`, nor in any background timer).
  - It also has ZERO test coverage anywhere in `tests/` or `src/`. Terminal rows (`delivered`, `abandoned`) will accumulate without bounds in production.

## RESIDUAL

1. **Terminal obligation pruning is uninvoked runtime dead code**:
   `DeliveryLedgerService::prune_terminal_obligations` (`src/ledger/service.rs:541`) is never called by production code. Hermes runs `_prune()` on every `record_obligation` call (`gateway/delivery_ledger.py:178`), and cleans up terminal entries (`delivered`, `abandoned`) older than 7 days or capping total rows at 500. In `omon-gateway`, terminal rows will accumulate indefinitely in SQLite.
2. **Missing boot or record integration for obligation pruning**:
   Neither `src/main.rs` (which prunes old `cron_runs` via `prune_terminal_cron_runs` at line 725) nor `record_obligation` (`src/ledger/service.rs:374`) invokes `prune_terminal_obligations`.
3. **No test coverage for `prune_terminal_obligations`**:
   Zero unit or integration tests invoke or assert behavior on `prune_terminal_obligations`.

REMAINING: Terminal obligation retention bounds and pruning (`prune_terminal_obligations`) are uncalled in production runtime and unpinned by tests.
